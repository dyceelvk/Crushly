# Independent Whisper state-machine experiment — NOT deployable

The three `07`–`09` files are for a disposable database only; never put them in production migrations. They adapt only the request/accept/insert-guard portion of the older v3 experiment to the follow + Homies pair lock. The old prototype's unrelated Keep/subscription code is intentionally excluded.

The experiment snapshots currently open conversations as accepted without depending on relationships; closed/blocked threads stay unavailable. It sets up a request-first preference, preserves the legacy everyone-message preference, caps unaccepted sender inserts at two even if messages are deleted, treats a recipient reply as acceptance, permits explicit acceptance, and keeps open-setting-started threads accepted when the setting is switched off. Blocking shares the pair lock and marks permission blocked. Existing SQL tests include preservation, quota, deletion, reply, durable open preference and block; 20 concurrent two-message quota races passed.

**Release blockers:** does NOT wire the real send/open/list/read/media/notification/presence/receipt/call APIs, Realtime, app UI, local caches or client upgrade policy. Existing legacy `disconnect_pair` closes conversations, legacy RPCs may reopen them, and older clients have incompatible behavior. A sender can reach actual messaging through several paths (ordinary, Moment replies and post shares); all must enforce the same quota and eligibility without exposing content to unauthorized users. Realtime join permissions may be cached for existing sockets, so block revocation needs a separately verified solution, not just new-row policies. Lock order/races with all actual write paths need scrutiny, and no old real data may be put in fixtures. The raw test inserts are synthetic owner operations to exercise the trigger; they do not prove actual service integration. Adult age gate remains on.
