## The finding that changed the plan

Before writing anything I compared the repo to production. **They disagree.**

The repo folder holds 27 migration files. The live database has **39 applied migrations**. Twelve of the applied ones have no file in the repo, and the numbering has diverged:

And `20261028000028/29` in prod are the repo's `20261028000026/27`. So the repo's `026`/`027` are a **different pair of migrations** from prod's `026`/`027`. Numbering is no longer a shared coordinate system.

**Consequence: you cannot rebuild this database from this repo.** A fresh environment built from `supabase/migrations` would be missing comment threading, post saves, media security, feed pagination and vibe reactions — and would look like a working app until someone tried to comment, save or upload.

This is the single most important thing to fix, and it is bigger than any UI work. I have not fixed it here; recovering twelve migrations from `pg_get_functiondef` and hand-writing them as files is a task in itself and would be inventing history. What I did do is state it plainly and leave the two new migrations numbered non-collidingly (`20261030220000`, `20261030221000` — matching the timestamp style prod already uses for its ad-hoc ones).

## A — Schema (applied to production)

### `20261030220000_post_reaction_kinds.sql`

`post_reactions` had only `(post_id, user_id, created_at)` — a like was a boolean. `moment_reactions` has carried a `kind` all along. This gives a post the same five words: **crush, fire, laugh, wow, clap**.

- `kind text not null default 'crush'` + a check constraint, so existing rows mean what they meant before.
- `react_to_post(p_post_id, p_liked, p_kind)` — the old 2-arg function was **dropped in the same transaction**, following the precedent in `20261012000025`. Without that drop, PostgREST would see two candidates for a 2-arg call and answer 300.
- `post_engagement()` now also returns `myReaction`, `reactionKinds` (a breakdown by kind), and `saved`. Because both the feed and the post view build engagement through this one function, the breakdown reached both at once.

### `20261030221000_post_comment_likes.sql`

`post_comment_likes` has existed since the comment work landed, and `post_comments_feed` **already counted it** — but no function ever wrote to the table, so the count was always zero. `like_post_comment(comment_id, liked)` is the missing write path, with the same audience and block rules as the comment itself.

### Verified after applying

```
kind column              → 1
react_to_post overloads  → p_post_id bigint, p_liked boolean, p_kind text   (exactly one)
older rows backfilled    → 1
post_engagement keys     → liked, saved, likeCount, myReaction, commentCount, reactionKinds
```

### Rollback

Both are additive. To undo:

```sql
drop function if exists public.like_post_comment(bigint, boolean);
alter table public.post_reactions drop constraint if exists post_reactions_kind_check;
alter table public.post_reactions drop column if exists kind;
-- then restore the 2-arg react_to_post and the previous post_engagement,
-- both of which are quoted verbatim in this conversation's captured
-- pg_get_functiondef output.
```

## B — One player, one window

### `src/lib/playerFocus.ts` (+ 7 tests)

`EditedClip` mounted a `useVideoPlayer` **per card** with `autoPlay`, and nothing coordinated them — a Flow with three clips played three soundtracks over each other. Now a module-level registry enforces one holder: `takeFocus` silences every other registered player, `registerPlayer` returns its own unregister, `releaseFocus` hands the sound back to nobody.

### `src/lib/feedWindow.ts` (+ 13 tests)

The arithmetic of a mounted window around the active post (radius 1: the one you left, the one you are on, the one you are about to reach). `isAudible` is true for exactly one index.

### `src/lib/viewability.ts` (+ 9 tests)

Turns scroll offset + card boxes into the active post id, using a focus line at 45% of the viewport rather than "most visible card", because a feed is read top-down.

### Wired in

`Flow.tsx` measures each card with `onLayout`, tracks scroll, and passes `active` to `PostCard`, which now does `autoPlay={active} loop={active}`. `Circle` and other callers are unaffected — `active` defaults to `true`.

**Combined effect:** the windowing stops off-screen clips from mounting decoders, and the registry guarantees that even if two end up mounted, only one is heard.

## C — The viewer rebuilt

`PostViewer.tsx` was a single `ScrollView` stacking author, title, body, media, counts, actions and a flat comment list — so the clip slid away as you read and comments were always below the fold. It is now one deliberate surface:

- **Fixed media stage** with top and bottom scrims, photo or clip full-bleed.
- **Right rail**: react · comment · keep · share. Long-press react opens the five-kind picker; double-tap the video reacts `crush`.
- **Caption block** with author, expandable body, and a reaction breakdown (`❤️🔥 1.2K reacted`) instead of a bare number.
- **Docked control plane** with an always-present composer and a Whisper button for mutuals.
- **Comment sheet** with real threading (replies hang off parents, one level deep as the database enforces), comment likes wired to the new RPC, an author badge, `canDelete` respected, and a reply-to bar.

`formatCount` was pulled out to `src/lib/counts.ts` (+ 9 tests) so it could be tested without RN — it honours what the TikTok evidence showed: honest below 10⁴, shortened above.
